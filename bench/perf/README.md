# Performance benchmark

Compares the runtime performance of `@hpke/core` + extension packages with
[panva/hpke](https://github.com/panva/hpke) on Node.js, using the same cipher
suites as [`bench/bundle`](../bundle/README.md).

`@hpke/*` packages are built from the current repository sources. panva/hpke
(`hpke`, plus `@panva/hpke-noble` for ChaCha20Poly1305 / ML-KEM / X-Wing) comes
from `node_modules`. esbuild bundles an adapter for each library and suite
(`bundle`, ESM, `target=esnext`, no minification), and Node.js loads the
results. Both libraries go through the same build pipeline and the same
measurement loop. Adapter sources are generated in
[`src/libs.ts`](./src/libs.ts).

Before measuring, the tool checks each suite for interoperability. Key pairs are
generated by each library, and each library opens messages sealed by either
library.

## Usage

Requires Node.js >= 24 and npm.

```sh
cd bench/perf
npm ci
npm run bench
```

Results are written to `results.md` and `results.json`, which are ignored by
Git.

To select suites or operations, or change the measurement parameters:

```sh
npm start -- --filter x25519
npm start -- --filter mlkem --op seal --op open
npm start -- --time 3000 --rounds 6 --payload 1024
```

Use `npm start -- --help` for all options and `npm run typecheck` to type-check
the tool.

## Operations

| Operation  | Timed                                                              |
| ---------- | ------------------------------------------------------------------ |
| `keygen`   | Key pair generation                                                |
| `seal`     | Single-shot seal (Base mode): encap, key schedule and AEAD encrypt |
| `open`     | Single-shot open (Base mode): decap, key schedule and AEAD decrypt |
| `ctx-seal` | AEAD encryption on an established sender context (`Seal` / `seal`) |

Key deserialization, the reference ciphertext for `open`, and sender context
setup for `ctx-seal` are prepared outside the timed loop. The plaintext is 64
bytes by default (`--payload`), and the AAD is 16 bytes.

## Measurement

For each suite and operation, both libraries first run a warm-up (`--warmup`,
default 300 ms). The measurement time (`--time`, default 1000 ms per library) is
then split into `--rounds` rounds (default 4), and the library order alternates
between rounds to reduce ordering and thermal bias. Each iteration is timed
individually. The reports show ops/s (1000 / mean), the mean time, and the
relative margin of error of the mean (95% confidence).

`ratio` is `@hpke ops/s / panva ops/s`. A value above 1 means `@hpke` is faster.

Results depend on the machine, the Node.js version and its Web Cryptography
implementation, so compare runs only on the same environment. The Markdown and
JSON reports record the revision, Node.js version, platform, CPU and parameters.

## Cipher suites

Definitions are in [`src/suites.ts`](./src/suites.ts), and the set is kept in
sync with `bench/bundle`.

| KEM                        | KDF         | AEAD             |
| -------------------------- | ----------- | ---------------- |
| DHKEM(P-256, HKDF-SHA256)  | HKDF-SHA256 | AES-128-GCM      |
| DHKEM(P-384, HKDF-SHA384)  | HKDF-SHA384 | AES-256-GCM      |
| DHKEM(P-521, HKDF-SHA512)  | HKDF-SHA512 | AES-256-GCM      |
| DHKEM(X25519, HKDF-SHA256) | HKDF-SHA256 | AES-128-GCM      |
| DHKEM(X25519, HKDF-SHA256) | HKDF-SHA256 | ChaCha20Poly1305 |
| DHKEM(X448, HKDF-SHA512)   | HKDF-SHA512 | AES-256-GCM      |
| ML-KEM-768                 | HKDF-SHA256 | AES-128-GCM      |
| X-Wing (MLKEM768-X25519)   | HKDF-SHA256 | AES-128-GCM      |
